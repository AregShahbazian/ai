`/usr/lib/{i386,x86_64}-linux-gnu/`.

`unattended-upgrades` is disabled. Four `6.11.0-17` (HWE) kernel packages are
held — deliberate, from past touchpad breakage. Keeping them held costs

**Not the cause of the slowness.** 30 G RAM with 24 G free, disk at 40%, load

`~/.claude/system.md`). Nothing found that explains it. This cleanup is
hygiene, not a fix.

**gnome-remote-desktop**: initially flagged as an open door — that was wrong.
RDP and VNC are both `false`, nothing listens on 3389/5900, ufw is active. It
ships stock with Ubuntu GNOME. Left alone deliberately.

# ROUND 2 — SDR + repo leftovers (same day)

Triggered by `apt update` erroring after the Tailscale purge.

## Repo leftovers

Purging `tailscale-archive-keyring` removed the signing key but left
`/etc/apt/sources.list.d/tailscale.list`, so every `apt update` failed
signature verification (`NO_PUBKEY 458CA832957F5868`). Docker was the same
situation one step behind — repo still configured, not erroring only because
`/etc/apt/keyrings/docker.asc` was a manually-installed file no package owned.

Removed: `tailscale.list`, `docker.list`, `docker.asc`,
`ettusresearch-ubuntu-uhd-noble.sources`, `ubuntu.sources.curtin.orig`
(inert installer backup — apt reads only `.list`/`.sources`).

`apt update` now clean. 6 sources remain, all live.

## SDR removal

~60 apt packages: full GNU Radio stack, SoapySDR with every hardware module
(Airspy, BladeRF, HackRF, LimeSDR, RTL-SDR, USRP, RedPitaya, RFSpace,
MiriSDR), plus the `gqrx-lool` snap. **~9 G.**

The Ettus PPA turned out to be providing nothing — all installed `uhd`
packages came from `noble`/`noble-updates`.

### Python safety check (the reason this needed care)

GNU Radio orphaned 35 `python3-*` system modules. Apt's "no longer required"
only tracks *package* dependencies — a personal script with a
`#!/usr/bin/python3` shebang would break silently.

Procedure used, worth repeating:
1. Found all scripts with a system-Python shebang (19, excluding venvs,
   node_modules, site-packages, miniconda3, pyenv).
2. Extracted their imports.
3. Intersected imports against the orphan list.

**Exactly one overlap: `numpy`**, used by `~/bin/co/mediadedupe.py`.
Every other numpy consumer (`stable-diffusion-webui`, `bot1`, `ml/`,
`doctor/`) has its own venv/conda env. `PIL` was `python3-pil`, not orphaned.

Fix was one line: `sudo apt-mark manual python3-numpy`.
Verified after: `import numpy, PIL` → `mediadedupe OK`.

Checked before deleting `~/.gnuradio` and `~/.config/gqrx`: only generated
config stubs, zero `.grc` flowgraphs or captures anywhere in `$HOME`.

## Recoverability note

Package *files* cost only bandwidth to restore. Package *state* does not:
purged `/etc` configs come back stock (customizations lost), and data dirs
(`/var/lib/mysql`, docker volumes, `/var/www`) are never restored by
reinstall. Rule: packages are cheap, state is not — look inside any
`~/.config/*` or `/var/lib/*` before `rm -rf`.

# CORRECTION — unattended-upgrades is NOT disabled

The audit reported it disabled. That was wrong, and wrong the same way the ufw
call was wrong: I read a **systemd unit state** instead of the mechanism that
does the work.

**Actual state — automatic security patching has been running all along:**
- `/etc/apt/apt.conf.d/20auto-upgrades`: both `Update-Package-Lists` and
  `Unattended-Upgrade` = `"1"`. Untouched since 2024-02-12 (package default).
- Last run **2026-09-01 11:20**, continuous log history back to March 2026.
- `apt-daily-upgrade.timer` enabled; fired 2026-09-02 12:30, next 09-03 06:12.
- Origins include `noble-security` + UbuntuESM security pockets.

**Why the misread:** `unattended-upgrades.service` reports `disabled`, but that
unit is only the *shutdown-time* hook. The real driver is
`apt-daily-upgrade.timer` → `apt-daily-upgrade.service`, which reads the
`APT::Periodic` config. Unit disabled, function working.

Ubuntu Desktop enables this on a fresh install; this machine is still stock.
Nothing to enable. The `dpkg-reconfigure` suggestion was unnecessary.

## Lesson (applies to both misreads)

On Ubuntu, `systemctl is-enabled` / `is-active` describes the **unit**, not
always the **function**:
- **ufw** — unit enabled + active, firewall doing nothing (`ENABLED=no` in
  `/etc/ufw/ufw.conf`).
- **unattended-upgrades** — unit disabled, patching working (driven by
  `apt-daily-upgrade.timer`).

Both times the **config file was the truth.** Check config and logs, not unit
state, for anything config-driven.
